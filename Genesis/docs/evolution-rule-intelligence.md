# Evolution rule intelligence

The private workflow connects the nine detector rules, authoritative Python evidence, recorded Gemini suggestions and immutable human reviews. Public visitors retain the same baseline source cases and risk scores. Discovery is an explicit operator-only switch exposing 40 existing cases; selection and held-out cases are rejected by operational reads and triage.

## Investigation records

Execution remains A1 → A2 → A3 → A4 → A0. A2's five advisory dimensions are a separate opinion: Python computes their weighted total and flags absolute differences above 0.15. Missing inputs remain unavailable. A3 may record up to three secondary typologies; A4 records self-assessed evidence confidence and a cited reason. Confidence is not a probability or certainty of wrongdoing. New prompts and schemas are immutable configuration components. Historical records remain unchanged and absent fields display “Not recorded.”

Expandable traces derive Not started from absent attempts and preserve recorded running, failed and unknown states. Only validated successful steps expose output. A5 has its own trace against its analytical run, never an investigation completion check.

## Matrix, report and publication

Evolution leads with the selected full analytical report and synchronized Outcomes/Configuration matrix views. All nine rows remain present without reviews. Counts use distinct reviewed alerts; FP proportions divide by conclusive human reviews. Inconclusive, unavailable predictions and uncertain machine labels remain separate. Signals and secondary typologies overlap; operational agreement is not population accuracy or held-out FPR.

Supporting alerts open private evidence and an in-memory return to the selected rule. Filters, drafts, identities and authentication do not enter URLs or browser storage. Navigation guards unsaved drafts; explicit discard clears them across Evolution forms.

Publications require an operator-reviewed executive summary, preview and explicit confirmation. The server publishes only allowlisted aggregate counts from frozen report inputs and the reviewed text, with scope, sample sizes and publication time. Immutable versions have an audited, revision-checked active pointer. Withdrawal removes the active public brief without deleting its history. Public reads use `no-store`; private reviews never update the public brief automatically. Publication privacy checks cannot replace the operator's review of free-text wording.

## A0 learning

Cutoffs remain separate from detector policy. The additive heuristic is unchanged: LOW_RISK +0.50, CLOSE +0.30, HIGH uncertainty +0.20. Baseline TP ≤0.25 / FP ≥0.65; missing context and protected signals force uncertainty.

One preparation evaluates all eligible rules. It requires 30 genuine conclusive reviews overall and 15 compatible scored target-rule reviews, with at least two TP and two FP identities. Training references, cohort, method, thresholds and freeze time are hashed. The fixed cutoff grid and deterministic tie-breaking prohibit increases in either classification-error direction and require a correct FP uncertainty resolution.

Validation opens once on the first five eligible reviews submitted after freeze, from distinct identities outside training. Both human classes and safe measured benefit are mandatory. It cannot substitute the synthetic held-out comparison or replace failed validation samples. Approval, rejection, application and rollback use revisions; approval changes no policy. Application atomically creates an immutable A0 configuration and updates a separate pointer. New parents pin both detector and A0 policies.

Explicit reassessment uses stored compatible evidence, at most 50 alerts per call, with a cursor for continuation. It appends assessments only for completed unreviewed uncertain alerts. Frozen, concurrently changed and in-progress alerts are skipped. Repeats are idempotent. Rollback allows explicit restoration of affected unreviewed assessments. Feedback pins the assessment actually displayed and rejects a stale selection. No model call or sealed-output rewrite occurs during reassessment.

## Release boundaries

The Firestore index configuration includes the new bounded learning/assessment histories and supporting-feedback reads. Deploy these indexes before enabling the corresponding cloud journeys. No direct browser Firestore access is introduced.

Executable detector changes remain HIGH_VALUE allowlisted and evidence-gated. Other rule recommendations are informational. A0 improvements concern heuristic labels, not generated-alert reductions. The existing `hv-15000` comparison remains unsupported with no measured improvement. Prompts, weights and model choice have no operator learning/application workflow.

Genuine local evidence and isolated tests are recorded in implementation status. Insufficient samples are a valid outcome. Cloud build/update spending, Vertex activation and public repository publication remain separate gates.
